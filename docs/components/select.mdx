## Example

Options are `SelectOption` children. `Select` reads their values and labels and hands them to Base UI, so the page has no native `<select>`. The list opens 5px below the trigger instead of covering it; the selected option has a check, and disabled ones are faded. The trigger is a field: it takes the same `size` and `shape` as [Input](https://design.iff.day/components/input).

## Inline

`variant="inline"` draws the field as text in a row of filters, such as Type: All in the festival directory, and shows a box only on hover. `active` turns it brand red on a light red ground once the filter is applied. `title` puts the filter's name inside the trigger (Type: All), so name, value and chevron are one control with one hover. An `Input` takes the same variant, with an underline in place of the box. A select keeps its focus ring for the keyboard only: after a choice made with the pointer it is not outlined.

## Usage

- Values are strings. Numbers work too, but `onValueChange` receives a string; convert it back where needed.
- An empty string can stand for All or None: the poster language filter and No rating both do this.
- With a handful of options that readers should see at once, consider `Tabs` or a row of buttons.
