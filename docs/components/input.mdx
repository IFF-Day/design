## Example

An input is a light grey rounded box without an outline. On focus it turns white, with a stronger border and a 3px focus ring; disabled, it fades to 45%. `Textarea` is the same Base UI Input rendered as a multi-line box, so `Field` and `Form` validate it too.

## Sizes

`size` takes the five control sizes, from 26px to 52px, with the same type size as the button of that size, so a field and its button stand level. The default is `base`, 38px and 14px type. Tool rows and tables use `sm`, the search page `lg`. `shape="pill"` rounds the ends, for a row of pill buttons.

## Prose

`variant="prose"` turns a field into a writing surface: an input becomes a title at 24px (18px on phones) and a textarea a body at 16px with a line height of 1.75, its height set by `rows`. The article editor and the blog editor in the CMS use it.

## Usage

- An input on its own needs an `aria-label`; inside a `Field`, the field’s label names it.
- The placeholder is a light grey hint that disappears on typing, so it never replaces a label.
- An icon inside the field goes through [InputGroup](https://design.iff.day/components/input-group). On a grey panel, the panel sets the `--field` tokens; see [Field](https://design.iff.day/components/field).
- Pages place inputs (width, flex, margins) and never restyle them: a stylesheet rule that changes an input’s fill, border, padding, type or height fails `tests/ui-boundary.test.ts`, and so does a native `<input>`.
